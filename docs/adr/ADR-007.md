# ADR-007: Registry Auto-Discovery

**Status**: Accepted — Phase 1 now, Phases 2-3 with marketplace
**Date**: 2026-02-18

## Context

Adding a new theme currently requires 6 manual touch points:
1. Foundation JSON in `packages/foundations/data/<name>.json`
2. Import in `packages/foundations/src/index.ts`
3. Entry in `scripts/generate-themes.ts`
4. Generated output in `packages/themes/src/<name>/`
5. Manual `index.ts` in `packages/themes/src/<name>/index.ts`
6. Export in `packages/themes/src/index.ts`

This is fragile and does not scale to 10 curated themes or community contributions. The whitepaper envisions a registry where new themes extend the catalog without modifying core packages.

## Decision

**Three phases, each additive**:

### Phase 1 — File system discovery (implement now)

The generator script scans `packages/foundations/data/*.json` automatically:
```typescript
const foundationFiles = readdirSync(DATA_DIR).filter(f => f.endsWith('.json'));
for (const file of foundationFiles) {
  const data = JSON.parse(readFileSync(join(DATA_DIR, file), 'utf-8'));
  validateFoundationData(data); // against JSON Schema
  await buildAndWrite(data, file.replace('.json', ''));
}
```

`foundations/src/index.ts` and `themes/src/index.ts` are **generated files** — produced by the generator, not handwritten. Adding theme 3 = drop one JSON file, run `pnpm build`.

**Touch points reduced from 6 to 1.**

### Phase 2 — npm package discovery (Stage 3, marketplace)

Community themes publish as standalone npm packages:
```json
{
  "name": "@author/syncupsuite-theme-nordic-modern",
  "keywords": ["syncupsuite-theme"],
  "main": "foundation.json"
}
```

The `@syncupsuite/theme-loader` package (new) discovers installed `syncupsuite-theme` packages at build time and includes them in the generation pass. The `FoundationData` JSON Schema is the stable contract.

### Phase 3 — HTTP registry (post-launch)

A Cloudflare Worker serves the theme registry. BrandSyncUp's theme browser fetches the registry, themes are loaded on demand via dynamic import. This enables the "curated + community" marketplace model without requiring consumers to install every theme.

**The `FoundationData` JSON Schema** is the stable contract across all three phases. It must be published alongside the packages as `@syncupsuite/tokens/schema/foundation.json`.

## Consequences

**Positive**:
- Phase 1 eliminates the scaling bottleneck immediately
- The community contribution path (Phase 2) has a clear, JSON-Schema-validated contract
- Phase 3 enables the theme browser UI without npm install overhead

**Negative**:
- Generated barrel files (`index.ts`) cannot be manually customised — any customisation must go in the generation template
- Phase 1 requires the generator to be idempotent (safe to re-run)
- Phase 2 npm discovery adds a build-time `node_modules` scan — slow for large installs
