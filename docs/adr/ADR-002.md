# ADR-002: Semantic Layer Isolation

**Status**: Accepted
**Date**: 2026-02-18

## Context

The semantic token layer (`tokens.semantic.light` / `tokens.semantic.dark`) maps primitive tokens to use-case names (`background.canvas`, `text.primary`, `border.subtle`). Currently, some semantic tokens in `buildSemanticTokens` use absolute hex values (specifically status colors: `#DC2626`, `#EF4444`) rather than DTCG references to primitives.

This creates an inconsistency: most semantic tokens are pure mappings (`{primitive.color.neutral.50}`) but protected tokens are hardcoded values. The inconsistency makes the tier governance model harder to reason about — T1/T2 overrides would need special-case handling for these tokens.

Additionally, the semantic layer has no formal contract for which paths are required — `REQUIRED_SEMANTIC_TOKENS` in `constants.ts` defines the required set, but there is no type that enforces the shape.

## Decision

**Rule**: Semantic tokens are a mapping layer only. They reference primitives via `{path}` syntax — never absolute values.

**Exception**: Protected status tokens (`status.error.*`, `status.success.*`, `status.warning.*`, `focus.ring`) may use absolute values only when:
1. The value must be identical across all foundations (WCAG-mandated), AND
2. The token is in `PROTECTED_TOKEN_PATHS`

This exception is explicitly documented in the token definition as `$extensions.syncupsuite.absolute: true`.

**Implementation**:
- Add `$extensions.syncupsuite.absolute: boolean` to `DTCGToken` type
- `validateOverride` rejects any override targeting `absolute: true` tokens
- `buildSemanticTokens` documents why status colors use absolute values
- All other semantic tokens must use `{reference}` syntax — enforced by `validateSchema`

## Consequences

**Positive**:
- T1/T2 overrides have a clear rule: they modify which primitive a semantic token points to, never the primitives themselves
- The semantic layer is human-readable as a pure mapping document
- `validateReferences` can enforce that all non-absolute semantic tokens resolve

**Negative**:
- Status color values cannot be tuned per foundation (intentional — accessibility guarantee)
- Small additional complexity in `validateSchema` to check reference vs absolute consistency
